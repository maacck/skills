概要

三个组件

固定的 index.html（全部方案列表）、固定的 project.html（单个方案的 app shell：结构化的方案、实现、进度）、agent 按方案生成的 visual-plan.html / visual-impl.html

向后兼容

固定页面宽容解析，认不出的块或整篇显示原文 md，不报错

可视化文档保真

可以重组、突出、画图，但不能丢信息；用 data-src 标记 + 脚本检查覆盖率

过时由脚本判定

HTML 内嵌 md 的 version_hash 与逐单元哈希；visual-status.mjs 报告哪些单元变了，gate 前必须同步到 fresh

两个询问点

plan.md 首稿完成后问是否生成 visual（同意则 visual-impl 在 impl 首稿时自动生成）；执行开始前问是否打开进度页

最弱环节

哈希只能证明"覆盖了、且基于最新 md 盖章"，不能证明改写忠实；措辞忠实度仍要人看

成功检查

  1. 浏览器打开 / 列出 .plans/ 下全部方案
  2. /p/<dir> 显示该方案的 Plan / Impl / Progress，改 impl.md 或新增 runs/T1-1/handoff.md 后 ≤1s 自动刷新；旧格式或无法解析的部分显示原文
  3. subagent 按指南生成 visual-plan.html，visual-status.mjs --stamp 通过保真检查并写入哈希，在 Visual 标签页和 file:// 都能正常显示
  4. 修改 plan.md 中一个 ADR 后，visual-status.mjs 报告 stale 并列出该 ADR、退出码 1，shell 显示"已过时"；只改任务状态或追加日志时仍为 fresh

约束

  • 零 npm 依赖、无构建步骤：scripts/ 下是手写的 ESM .mjs，只用 Node 标准库；前端库走 CDN（jsDelivr，锁大版本，URL 已验证可访问）
  • Node ≥ 20（fs.watch recursive 在 Linux 需 20+；本机 v22.23.2）；lint 因此也依赖 Node
  • 只读：server 不写任何文件（.viewer.json 除外），只绑定 127.0.0.1
  • md 是唯一事实来源；visual 文档是派生物，与 md 冲突时以 md 为准
  • 解析只锚定 Fixed 追踪标记，不依赖可被翻译的章节标题

  • 增量同步只改变化单元，省 token
